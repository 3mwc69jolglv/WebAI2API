## 1. Gemini (gemini.google.com)

**Protokol bersama (semua implementasi sepakat):** `POST https://gemini.google.com/_/BardChatUi/data/assistant.lamda.BardFrontendService/StreamGenerate`, `Content-Type: application/x-www-form-urlencoded`, body `f.req=<JSON nested-array>` (+ `at=<XSRF token>`, `bl=<build label>`, `authuser=<account index>`). Respons: line-delimited `wrb.fr` JSON; `arr[0][2]` adalah inner JSON string; teks kandidat di `inner[4]`. Katalog model live via batchexecute RPC `otAQ7b`. **Gotcha kritis:** auth invalid/expired diam-diam degrade ke anonymous — tetap dapat 200, tapi bukan model yang diminta.

### 1a. Sophomoresty/gemini-web2api — implementasi referensi
- https://github.com/Sophomoresty/gemini-web2api · Python · MIT · ~3.458 ★ · original yang hampir semua repo lain fork/port/kutip.
- OpenAI-compatible `/v1/chat/completions` + `/v1/models`, plus `/v1/responses` (Codex CLI) dan `/v1beta/models/{model}:generateContent|streamGenerateContent`.
- Auth: anonim untuk teks dasar. Opsional cookie file: `SID`, `HSID`, `SSID`, `APISID`, `SAPISID`, `__Secure-1PSID`. Tambah `auth_user`, `xsrf_token` (`SNlM0e` → field `at`), `gemini_bl`, `temporary_chats`. Klaim: routing Pro asli butuh cookie Gemini Advanced berbayar; cookie akun free "authenticate tapi diam-diam fallback ke Flash" (konflik dengan implementasi baru — verifikasi live).
- Web calls: `StreamGenerate` dengan payload nested-array `f.req`; model via field `[79]` (`MODE_CATEGORY`); `bl` dari config.
- Streaming: SSE via `httpx`; parse baris `wrb.fr` → inner JSON → teks kandidat dari `inner[4]`.
- Vision: pesan multimodal gaya OpenAI (URL atau base64 data URL); pakai endpoint upload gambar Gemini Web; README warning: upload mungkin butuh cookie.
- Thinking: nama model `-thinking` terpisah dipetakan via field `[79]`; plus klaim suffix `@think=N` (0 = terdalam … 4 = terdangkal) — **disputed, lihat debunk di §1b**.
- Web search: "built-in internet access" warisan dari backend web; tidak ada flag search per-request yang didokumentasikan.
- Pitfalls: single-turn saja (multi-turn disimulasikan dengan melipat history ke prompt); Google bisa throttle pemakaian berat (auto-retry); Docker default bridge networking bisa hasilkan respons kosong (`content: null`) — pakai host networking.

### 1b. zexadev/gemini-web2api-go — paling aktif dirawat, paling lengkap
- https://github.com/zexadev/gemini-web2api-go · Go · MIT · ~616 ★ · 200 commit · single binary + dashboard admin + SQLite/MySQL/PostgreSQL + MCP server + `/v1/videos`. Dokumentasi terbaik, termasuk angka anti-abuse terukur.
- `/v1/chat/completions`, `/v1/models`, `/v1/responses`, `/v1/videos` (video async: create → poll → download MP4, butuh akun Pro login), MCP `web_search` tool di `/mcp`.
- Auth: cookie pool (multi akun, rotasi least-recently-used). Set cookie lengkap termasuk `__Secure-1PSIDTS`; `SAPISID` wajib (auto-hitung `SAPISIDHASH`). XSRF auto-fetch dari halaman Gemini, cache per cookie, self-healing saat expiry (XSRF hilang = semua request authed 400; anon tidak terpengaruh). **Auto-renewal:** `Set-Cookie` upstream refresh `SIDCC` / `__Secure-1PSIDCC` / `__Secure-3PSIDCC` ditangkap dan ditulis balik; tiap 10 menit keepalive ke `accounts.google.com/RotateCookies` — sentinel payload menerbitkan ulang `__Secure-1PSIDTS` (expiry ~30 menit). **Export cookie dari Firefox:** Device Bound Session Credentials (DBSC) Chrome mengikat sesi ke device, jadi `__Secure-1PSIDTS` hasil export Chrome rotasinya 401 dan akun mati dalam ~30 menit–jam. Tiap akun dipin ke satu egress IP ("sticky exit"). Hanya 401/403 yang dihitung fault cookie; cookie expired diam-diam degrade ke anonymous.
- Web calls: `StreamGenerate`, payload 80-slot + header model; katalog dari `batchexecute?rpcids=otAQ7b`; `bl` auto-follow. Mode: `multi_turn` (native `conversation_id` continuation — hanya pesan terbaru dikirim), `temporary_chat` (tidak masuk history/training akun), `auto_delete_conversation`, `anon_first` (request plain-text lewat anon untuk hemat kuota). Prompt panjang: dengan cookie, percakapan terlalu panjang auto-convert ke lampiran `message.txt`; tanpa cookie, 400 `context_length_exceeded`.
- Streaming: incremental asli untuk chat polos: `delta{role}` → `delta{content}`×N → delta kosong + `finish_reason` → `[DONE]`. Request dengan `tools` dan `/v1/responses` di-buffer lalu di-emit (blok `tool_call` penuh harus di-parse dulu). `X-Accel-Buffering: no`. `usage` dihitung lokal dengan tiktoken `cl100k_base`; `reasoning_tokens` dilaporkan terpisah, tidak termasuk `completion_tokens`. Backend tidak mengembalikan token count asli — semua usage estimasi.
- Vision / generation: khusus cookie. `image_url` (chat) dan `input_image` (responses), `data:` URL atau http(s), satu gambar cap 12 MB; upload resumable dua langkah ke `content-push.googleapis.com/upload/`; upload anonim sukses tapi mereferensikannya ditolak (`BardErrorInfo 1100`). Juga bisa baca video. Model generation lewat endpoint chat yang sama: `gemini-image` (Nano Banana) → markdown data-URL base64 di `content`; `gemini-music` (Lyria, ~30 dtk) → base64 `audio/mpeg`; `gemini-canvas` → blok ```html inline; `gemini-video` async. Byte produk diunduh server-side dan di-encode ulang (tidak pernah dibagikan sebagai URL berpagar cookie).
- Thinking: `-thinking` adalah **toggle UI yang ortogonal terhadap model dasar**, bukan model terpisah (3.6 Flash, 3.5 Flash-Lite, 3.1 Pro masing-masing punya varian thinking). `gemini-3.1-pro` meng-emit reasoning chain di setiap jawaban → diekspos sebagai `reasoning_content`; di streaming, semua delta thinking datang **sebelum** teks body. **Koreksi:** suffix `@think=N` **terbukti salah** — packet capture menunjukkan `inner[17]` adalah **index turn** dalam percakapan, bukan kedalaman thinking.
- Web search: native web search termasuk di semua model, termasuk anonim. Tambahan diekspos sebagai MCP `web_search(query)` yang mengembalikan jawaban tersintesis + daftar `Sources:`. `url_context` belum diimplementasikan; Deep Research belum diimplementasikan.
- Pitfalls (terukur): blocking **per egress IP + TLS fingerprint, bukan per akun** — akun berbayar tidak menaikkan threshold. Traffic burst kena 302 → `google.com/sorry/index` setelah **80–180 request**; blok auto-pulih setelah **~106–121 menit** (cooldown circuit-breaker ~120 menit). Pace lembut (10 req/menit) jalan 800 request tanpa blok. Connection reuse menambah kapasitas ~60%. Limit per-IP-slot: concurrency / RPM / RPH (default 5/30/80). Proxy pool: http/https/socks5/socks5h; begitu proxy dikonfigurasi tidak ada fallback ke direct; env `HTTPS_PROXY`/`ALL_PROXY` tidak dibaca. **TLS:** koneksi direct pakai `tls-client` (Chrome 146: JA3 + HTTP/2 SETTINGS + ALPS); via proxy fallback ke Go stdlib HTTP. Fingerprint SDK naive kena HTTP 429; fingerprint mirip Chrome kena halaman 302 sorry. **Prompt walls:** ~130k byte UTF-8 per body request; ~160k byte total terlihat via lampiran. Function calling di level prompt (model output blok ` ```tool_call``` `, di-parse regex) — bukan level protokol, tidak bisa benar-benar force. Estimasi token dalam ±20%.

### 1c. Godde3s/gemini-free-api — terbaru, desain guest-mode + rotasi cookie
- https://github.com/Godde3s/gemini-free-api · Go · MIT · ~9 ★ · dibuat 2026-09-09. Kecil/baru — kurang teruji — tapi mendokumentasikan dua mekanisme yang lain hanya menyiratkan.
- Single binary ~10 MB, tanpa DB. OpenAI `/v1/chat/completions` + Anthropic `/v1/messages`, keduanya dengan SSE; dashboard embedded dengan status akun live.
- Auth: **Guest mode jalan tanpa cookie** — klaim `StreamGenerate` menerima request tanpa cookie dengan `at` kosong (terverifikasi live menurut README, bahkan dari IP datacenter; klaim satu repo — perlu verifikasi independen). Dengan akun: `__Secure-1PSID` + `__Secure-1PSIDTS` (satu atau multi-akun JSON). Rotasi: `__Secure-1PSIDTS` segar dipanen dari respons (`Set-Cookie` + `RotateCookies`), disimpan ke `gemini-cookies-cache.json`; saat auth error coba `RotateCookies` sekali sebelum menyatakan akun mati. **Heartbeat proaktif:** panggil `RotateCookies` untuk semua akun tiap ~50 menit agar rantai cookie tetap hangat. Menyertakan tool Playwright `cmd/gemini-login` yang menangkap cookie otomatis. Token init per-akun (`SNlM0e` / `bl` / `f.sid`) di-cache dengan TTL 1800 dtk.
- Web calls: `StreamGenerate`; discovery model live via `otAQ7b`; menerima alias (`gemini-flash`, `gemini-pro`, `flash`, `pro`, bahkan hex id internal mentah); model tidak dikenal → default Flash.
- Streaming: SSE incremental asli dari **frame length-prefixed** Google — parser `frames.go` khusus digambarkan UTF-16-aware (satu-satunya repo yang menyebut framing secara eksplisit).
- Vision: `image_url` (data URI atau URL) → upload asli ke `content-push.googleapis.com` → Gemini benar-benar melihat gambar.
- Thinking: blok `thoughts` Gemini di-stream live sebagai `reasoning_content`; `THINKING=true` default, `reasoning:false` untuk menonaktifkan.
- Web search: tidak didokumentasikan terpisah (anggap warisan, belum terverifikasi).
- Pitfalls: pool multi-akun: round-robin + cooldown 429 eksponensial (basis 120 dtk, ×2) + failover transparan pre-first-byte; timeout antrean 120 dtk saat semua akun terbatas. Kode error upstream: `1060` = IP flagged (datacenter/VPN — ganti proxy), `1037` = kuota per-model. Cookie memberikan akses penuh akun Google — jangan pernah dibagikan.

### 1d. ikhsan3adi/gemini-web2api — port Go dari referensi Python, dengan impersonasi TLS
- https://github.com/ikhsan3adi/gemini-web2api · Go · MIT · ~42 ★ · rewrite Go lengkap dari implementasi Sophomoresty.
- `/v1/chat/completions`, `/v1/models`, `/v1/responses` (Codex CLI), `/v1beta/*` (Gemini CLI). Single static binary.
- Auth: lineage sama: `SID`/`HSID`/`SSID`/`APISID`/`SAPISID`/`__Secure-1PSID` di `cookie.txt`; `auth_user` + `xsrf_token` (`SNlM0e` → `at`); `gemini_bl` di config.
- Web calls: lineage `StreamGenerate` / `f.req` sama; config mencerminkan Python (`retry_attempts` 3, `retry_delay_sec` 2, `request_timeout_sec` 180).
- Streaming: SSE streaming; tidak ada detail parsing lebih dalam di README.
- Vision (eksklusif Go): intercept payload `image_url` (base64 dan URL eksternal), mulai sesi **Scotty Resumable Upload** di background, konversi gambar ke **WIZ blobs** internal Google, oper referensi gambar WIZ langsung ke Gemini; termasuk kompresi gambar bawaan.
- Thinking: klaim suffix `@think=N` sama seperti original Python — **anggap belum terverifikasi** per debunk zexadev (§1b).
- Web search: "built-in internet access" — warisan, tidak ada flag didokumentasikan.
- Pitfalls: impersonasi TLS via `tls-client` untuk bypass WAF di IP datacenter yang kena HTTP 403: `--impersonate chrome_120`, profil `chrome_112`–`chrome_130`, `edge`, `safari`. Catatan empty-response NAT Docker bridge (workaround host-networking sama).

### Layak diketahui juga (Gemini)
- **n0madic/go-gemini-web2api** — https://github.com/n0madic/go-gemini-web2api · Go, stdlib-only, ~3 ★. Kecil tapi **dokumentasi protokol terbaik**: seleksi model berbasis header (`x-goog-ext-525001261-jspb` = id model + kapasitas akun), katalog live via `otAQ7b`, `GEMINI_BL` auto-resolve dari halaman Gemini dan di-refresh berkala. **Set auth minimal:** hanya `__Secure-1PSID` + `__Secure-1PSIDTS` + `SAPISID` — `SID`/`HSID`/`SSID`/`APISID` legacy secara eksplisit **tidak diperlukan**, dan `__Secure-1PSID` saja diperlakukan stale/anonim. Rotasi `__Secure-1PSIDTS` via `accounts.google.com/RotateCookies` tiap 9 menit, ditulis balik ke file cookie jika file-backed. Cek auth: fetch `/app` dengan cookie — keberadaan `SNlM0e` berarti signed in; tidak ada = anonim. Gejala gagal auth: **body respons kosong**, bukan error. Vision butuh cookie terautentikasi; gambar di-upload fresh per request (TTL server-side ~24 jam). Limit prompt anonim ~30–40k token → muncul sebagai respons kosong 502. Usage diestimasi sebagai `chars / 4`. Bisa di-import sebagai library (`pkg/gemini` tanpa dependensi HTTP/CLI; `pkg/apiconv` memegang layer translasi). Model bagus untuk pemisahan modul port Rust yang bersih.
- **vitkuz573/gemini-proxy** — https://github.com/vitkuz573/gemini-proxy · **Rust** · MIT · 0 ★. Satu-satunya implementasi Rust yang ditemukan. **Dual mode:** API key resmi (`GEMINI_API_KEY` → `generativelanguage.googleapis.com`) **atau** mode cookie web-frontend (`GEMINI_COOKIES`, mis. `__Secure-1PSID` + `__Secure-1PAPISID`). API OpenAI + Anthropic + Responses, streaming dengan `stream_options.include_usage`, vision (base64/URL), thinking via `thinking_config` budget untuk model Pro, tool calling dikonversi ke function declaration Gemini, rate limiting per-IP, CORS. README-nya mereferensikan `docs/protocol.md` yang **tidak bisa diambil** (404) — detail protokol mode web belum terverifikasi dari README saja; baca `src/`-nya sebelum mempercayai. Tetap titik awal Rust terdekat yang ada.
- **Lineage pendukung:** **R3DMaNX/Gemini-API** (https://github.com/R3DMaNX/Gemini-API) — library `gemini-webapi` di balik seleksi model berbasis header dan logika kapasitas akun, termasuk header model kustom seperti `x-goog-ext-525001261-jspb: "[1,null,null,null,'<hex>',null,null,null,[4]]"`. **banana2556/gemini2api-cfworker** (https://github.com/banana2556/gemini2api-cfworker) — implementasi Cloudflare-worker: katalog model dari `GetUserStatus`, routing Pro akun berbayar via header `x-goog-ext` yang diturunkan dari id model + kapasitas, level thinking 1/2/3, dan diagnostik eksplisit (`pro_route_verified` / `configured_but_pro_unavailable` / `unverified`) untuk mengekspos fallback Pro diam-diam.

**Poin terbuka/konflik Gemini (verifikasi live):** Routing Pro — Sophomoresty/ikhsan bilang butuh Gemini Advanced berbayar; zexadev/n0madic melaporkan cookie akun free membuka 3.1 Pro asli (kemungkinan tergantung tier/versi — verifikasi via nama model yang dilaporkan server). `@think=N` terbukti salah, jangan implementasikan sebagai kedalaman thinking. Tidak ada repo yang mendokumentasikan flag search-enable eksplisit di payload `StreamGenerate`. Guest mode Godde3s adalah klaim satu repo yang butuh verifikasi independen.

## 2. ChatGPT (chatgpt.com)

**Protokol konsensus (semua project direct-transport sepakat):** `backend-api` privat, tidak didokumentasikan. Nama field, slug model, perilaku anti-bot sering berubah (slug di bawah dari era 2025–2026: `gpt-5`, `gpt-5-5`, `gpt-5-6`, `auto`, `o3`, `o4-mini`, dll).

**Auth — 4 bentuk kredensial, semua memberi header `Bearer` yang sama:**
| Kredensial | Cara dapat | Dipakai di mana |
|---|---|---|
| `access_token` (JWT, ~2 KB) | `GET https://chatgpt.com/api/auth/session` → `accessToken` | `Authorization: Bearer <access_token>` di tiap panggilan `/backend-api/*` |
| Cookie `__Secure-next-auth.session-token` | Cookie browser setelah login | `GET /api/auth/session` → `access_token` berumur pendek |
| OAuth `refresh_token` | Codex CLI `~/.codex/auth.json`, atau flow OAuth OpenAI | Ditukar dengan `access_token` segar |
| Cookie `_puid` + `ChatGPT-Account-ID` | Cookie browser / metadata akun | `_puid` sebagai cookie (Plus/Team); id akun sebagai header `Chatgpt-Account-Id` untuk workspace Team |

Jalur free/tanpa auth: UUID device ID acak sebagai akun free; kena endpoint anonim (`/backend-anon`) dan, untuk streaming, WebSocket (`/celsius/ws/user`) — tanpa `access_token`, chat/responses saja, tanpa file/gambar/TTS.

**Endpoint inti:** `GET /api/auth/session` (minting token); `GET /backend-api/models` (katalog per-akun asli, `models[].slug` → OpenAI `data[].id`); `POST /backend-api/f/conversation` (endpoint chat utama; `/backend-api/conversation` lama dan `POST /backend-api/conversation/init` juga teramati); `POST /backend-api/f/conversation/prepare` (mengembalikan `conduit_token` berumur pendek, dikirim sebagai `X-Conduit-Token`; gagal preflight tidak fatal); `GET /backend-api/f/conversation/resume` (melanjutkan stream panjang/terputus); `POST /backend-api/sentinel/chat-requirements/prepare` → `…/finalize` (handshake anti-bot); `GET /backend-api/conversations`, `GET /backend-api/conversation/{id}`, `PATCH /backend-api/conversation/{id}` (archive/delete), `GET /backend-api/me`, `GET /backend-api/accounts/check/v4-2023-04-27` (plan/fitur); `POST /backend-api/files`, `PUT <upload_url>`, `POST /backend-api/files/{file_id}/uploaded`, `GET /backend-api/files/download` (layanan file).

**Bentuk request `POST /backend-api/f/conversation`:** `action: "next"`; `messages: [{id, author: {role}, create_time, content: {content_type: "text", parts: [...]}, metadata}]`; `model` (slug); `thinking_effort`; `parent_message_id` (dibuat client, root); `conversation_id` (hanya saat melanjutkan); `timezone_offset_min`, `timezone`; `conversation_mode: {kind: "primary_assistant"}`; `history_and_training_disabled`; `supports_buffering`; `supported_encodings: ["v1"]`; `system_hints`; `enable_message_followups`; `client_contextual_info: {app_name: "chatgpt.com"}`; `paragen_cot_summary_display_override: "allow"`; `force_parallel_switch: "auto"`. Melanjutkan percakapan tersimpan menambah `conversation_id` + `parent_message_id` asli dan set `history_and_training_disabled: false`. Projects/GPTs pakai `conversation_mode: {kind: "gizmo_interaction", gizmo_id: "g-p-…"}` (projects adalah gizmo dengan `gizmo_type: "snorlax"`). Header tipikal: `Authorization`, `oai-device-id`, `oai-session-id`, `oai-client-build-number`, `oai-client-version`, `oai-language`, plus header gaya browser `Origin`/`Referer`. Nilai build/version `oai-client-*` opsional/disuplai operator — jangan hard-code nilai browser yang tercapture.

**Handshake Sentinel / anti-bot:** (1) `POST /backend-api/sentinel/chat-requirements/prepare` → `prepare_token`, `turnstile: {required, dx}`, `proofofwork: {seed, difficulty}`, `so: {collector_dx, snapshot_dx}` (persona `chatgpt-paid` vs `chatgpt-noauth`). (2) Selesaikan PoW secara lokal. (3) `POST …/finalize` dengan `{prepare_token, proofofwork: {seed, difficulty, answer}, turnstile, so}` → token berumur pendek. (4) **Diskrepansi algoritma PoW — verifikasi live:** PoW hasil capture octo-lex adalah `SHA-256(seed + counter)`, 3 byte pertama `< parseInt(difficulty, 16)`, terselesaikan dalam ~31 iterasi. gptweb2api malah mendeskripsikan array fingerprint browser 18-field, JSON-encoded + base64, di-hash dengan seed via **SHA3-512**, prefix digest hex ≤ difficulty, plus bootstrap proof (`gAAAAAC…`) yang digest SHA3-512-nya memenuhi difficulty `"0"`. Fork kecil juga melaporkan SHA3-512. Kemungkinan era/endpoint berbeda — jangan asumsikan salah satu tanpa capture live. (5) Turnstile (Cloudflare) dan challenge `so` (kemungkinan berbasis Kasada) adalah bagian sulit: project browserless entah menghilangkan Turnstile (jalan sampai enforcement aktif, lalu 403 → fallback browser) atau gagal tertutup. Tidak ada solver Turnstile/`so` lokal yang andal di repo-repo ini.

**Streaming — SSE JSON-patch v1:** `POST /backend-api/f/conversation` mengembalikan SSE. Event pertama `event: delta_encoding` / `data: "v1"`. Lalu campuran frame patch (`data: {"p":"","o":"add"|"replace"|"append"|"remove"|"bulk-patch","v":{"message":{…},"conversation_id":"…"},"c":0}` — terapkan patch untuk merekonstruksi message tree; jawaban panjang **tersegmentasi** dan segmen berikutnya me-replay tree yang sudah selesai) dan event bertipe (`resume_conversation_token`, `input_message`, `stream_handoff`, `server_ste_metadata`, `conversation_detail_metadata` membawa `limits_progress`, `message_stream_complete`, lalu `data: [DONE]`). Pelajaran kunci dari gptweb2api: pertahankan **ledger emisi per-turn + deteksi replay** (overlap kosakata) agar segmen yang di-resume/replay di-emit tepat sekali, berurutan, tanpa duplikasi atau pemotongan. `GPTWEB_STREAM_MAX_HANDOFFS` (default 64) membatasi budget segmen yang di-resume. Pesan snapshot kumulatif lama juga harus ditangani untuk kompatibilitas mundur.

**Vision / lampiran file — upload 3 langkah:** (1) `POST /backend-api/files` `{file_name, file_size, use_case: "multimodal", …}` → `{file_id: "file_…", upload_url}`. (2) `PUT <upload_url>` byte mentah, header `x-ms-blob-type: BlockBlob` (host `*.oaiusercontent.com`). (3) `POST /backend-api/files/{file_id}/uploaded` → `{download_url}`. Lalu pesan user memakai `content_type: "multimodal_text"`, `parts: [{content_type: "image_asset_pointer", asset_pointer: "file-service://<file_id>", size_bytes, width, height}, "<prompt>"]` plus `metadata.attachments: [{id, name, size, mime_type, width, height}]`. Gambar hasil generate kembali sebagai asset pointer di stream; unduh via `/backend-api/files/download` → URL estuary bertanda tangan. **Caveat:** pro-cli melaporkan `PUT` blob di-front Cloudflare dan menolak signature TLS non-browser (403 error 1010), jadi mereka menjalankan PUT di dalam halaman CDP; gptweb2api mengklaim PUT browserless jalan dengan `Content-Type` yang benar. Perlakukan upload browserless sebagai bergantung lingkungan. Limit: ≤10 lampiran/turn (gptweb2api); ≤8 gambar referensi di fork CDP.

**Thinking / reasoning:** Diminta dua cara: slug model (`gpt-5-5-thinking`, `gpt-5-6-thinking`, `gpt-5-6-pro`) dan/atau field `thinking_effort` (`none/minimal/low/medium/high/xhigh/max`; Aurora memetakan `reasoning.effort` Responses ke upstream `low/medium/high`). Katalog (`/backend-api/models`) mencantumkan per-model `reasoning_type` dan `thinking_efforts` yang diizinkan. Tipe konten stream: `thoughts`, `reasoning_recap`, `model_editable_context`, `text`; field metadata `initial_text` ("Reasoning"), `finished_text` ("Finished reasoning" / "Thought for 7s"), `finished_duration_sec`, `pro_progress`, `thinking_effort`, `model_slug` / `resolved_model_slug` / `did_auto_switch_to_reasoning`. **Jebakan (probe live pro-cli):** `thinking_effort` yang di-echo adalah cermin request, bukan bukti — `max` di-echo verbatim untuk model Pro yang tidak punya effort `max`, tanpa field stream yang membedakan effort yang diterapkan. Validasi terhadap katalog per-model, bukan echo. `paragen_cot_summary_display_override: "allow"` dikirim untuk mengizinkan tampilan ringkasan CoT.

**Web search / internet:** **Tidak ada repo yang mendokumentasikan flag `web_search: true` khusus.** Yang ada: *Native/auto* — model yang memutuskan; katalog model mengiklankan tool `search` per model. Metadata stream mengekspos `tool_invoked`, `tool_name`, `is_search`, `search_tool_call_count`, `search_tool_query_types`, `citations`, `content_references`, `search_result_groups`. `GET /backend-api/system_hints?mode=basic|connectors` melaporkan kapabilitas search/connectors. *Emulasi tool calling* (Aurora, chat2api): karena Web tidak punya function calling native, mereka menyuntikkan protokol teks `<tool_call>{…}</tool_call>` ke system prompt dan mem-parse blok `<tool_call>` kembali menjadi OpenAI `tool_calls`. Ini bisa membawa tool search sisi-client, tapi **server tidak pernah mengeksekusi tool** — client yang mengeksekusi dan mengembalikan hasil sebagai pesan `role: "tool"`. Aurora memaksa `stream=false` di mode tool-calling (butuh respons penuh untuk mendeteksi loop penolakan sandbox, `REFUSAL_RETRIES=3`). Deep Research / image-gen adalah tool/mode terpisah, bukan search polos. Chat sementara tidak punya tool gambar. **Gap untuk Rust:** untuk mendapat toggle search yang deterministik, harus capture request live dengan toggle search UI web menyala dan membedakan body — tidak ada README yang mempublikasikan diff itu.

**Pitfalls umum (semua repo):** Tidak ada endpoint limit/kuota standalone — pro-cli mem-probe ~20 kandidat (`/backend-api/usage`, `/me/limits`, dll), semua 404/405. Kuota hanya muncul sebagai `limits_progress` di dalam `conversation_detail_metadata` (counter `deep_research`, `odyssey`, `image_gen`). Throttling chat umum adaptif, tidak dipublikasikan. Plafon ukuran request ~150–200 KiB per request percakapan; gptweb2api mengonversi payload >96 KiB menjadi lampiran file JSONL (≤8 MiB/bagian, ≤32 MiB dokumen, ≤10 lampiran) alih-alih memotong. 401 → refresh token dan retry; 403 "Unusual activity" / `cf-mitigated: challenge` → masalah sentinel/TLS/proxy; `arkose token is required` / `turnstile token is required` → challenge yang tidak diselesaikan layanan; 429/5xx → backoff + cooldown akun. TLS fingerprinting penting: impersonasi `curl_cffi` Chrome/Safari, UA realistis + header `sec-ch-ua`/`sec-fetch-*`/`oai-language`, cookie `oai-did`/`__cf_bm`/`cf_clearance`. IP datacenter dan Chrome headless paling sering kena challenge. Token adalah kredensial akun: jangan pernah ekspos proxy secara publik, pakai key lokal `sk-…` yang kuat, simpan token ChatGPT server-side saja, rotasi cookie/token jika pernah ter-paste di mana pun. Risiko ban akun nyata; semua project menyangkal afiliasi dan mencatat interface privat bisa berubah kapan saja.

Hapus — `DELETE …/chat_conversations/{conv}` (verifikasi; satu dokumen menulis `/chat/{id}`).

**Body request completion (dari ekstraksi bundle frontend):** `prompt`, `parent_message_uuid` (pesan pertama: `00000000-0000-4000-8000-000000000000`), `timezone` (mis. IANA), `locale` (default `en-US`; allowlist termasuk `en-US,de-DE,fr-FR,ko-KR,ja-JP,es-419,es-ES,it-IT,hi-IN,pt-BR,id-ID`), `model`, `temperature`, `max_tokens_to_sample`, `paprika_mode`, `tools`, `tool_states`, `turn_message_uuids {human_message_uuid, assistant_message_uuid}`, `rendering_mode:"messages"`, `attachments`, `files` (array string `file_uuid`), `sync_sources` (array string uuid), `personalized_styles: [{key,type}]`, `custom_system_prompt`, dan pada pesan pertama dengan pembuatan inline (flag `claudeai_inline_conversation_creation`, default saat ini): `create_conversation_params {name, model, project_uuid, include_conversation_preferences, paprika_mode, compass_mode, create_mode, is_temporary, enabled_imagine, orbit_action_uuid}` — server lalu meng-emit event SSE `conversation_ready`. Ada juga varian transport gRPC saat caching diaktifkan; SSE adalah jalur yang didokumentasikan.

**Streaming — tangani KEDUA format:** *Legacy:* `{"type":"completion","completion":"<chunk>","stop_reason":…,"messageLimit":{…}}` (apa yang dilihat client lama; sebagian akun masih meng-emit). *Modern (gaya Anthropic):* `message_start` (membawa `message.uuid`, `parent_uuid`, `model`, `id: msg_…`, `trace_id`, `request_id`) → `content_block_start` → `content_block_delta` → `content_block_stop` → `message_delta` (`delta.stop_reason`: `end_turn|max_tokens|tool_use_limit|refusal|cyber_refusal|prompt_injection_risk|error|message_stop`) → `message_stop`. Event khusus: `conversation_ready`, `tool_approval`, `compaction_status`, `cache_performance`, `mcp_auth_required`. **Subtipe delta** di dalam `content_block_delta`: `text_delta` (`delta.text`), `thinking_delta` (`delta.thinking`), `thinking_summary_delta`, `thinking_cut_off_delta` (`delta.cut_off`), `input_json_delta` (arg tool), `signature_delta`. Tipe content-block: `text`, `thinking`, `tool_use`, `tool_result`. Frontend menerapkan "smoother" (buffering output); reimplementasi **tidak** boleh menyalin itu — teruskan delta stream secara langsung.

**Vision / input gambar (gambaran penuh):** Dua konsep: **`attachments`** = konten terekstrak inline (`{file_name, file_type, file_size:int, extracted_content, origin:"UserUpload", kind:"File", path?}`); **`files`** = referensi server-side di luar konteks (dikirim sebagai string `file_uuid` polos). Upload maks 50 MB (52.428.800 B); jika `extracted_content` melebihi limit in-context, konversi ke referensi `file` di luar konteks. Alur: wiggle upload → (dokumen saja) `convert_document` → responsnya **adalah** objek attachment untuk completion. `file_size` harus integer, tidak pernah null (upload bisa mengembalikan `size_bytes: null` → fallback ke panjang byte aktual), kalau tidak 400. `files` harus `[]` di alur doc-convert, bukan daftar UUID — jangan pakai `{"type":"tool_result","file_uuid":…}`. Gambar: wiggle upload saja, tanpa `convert_document`; model butuh `capabilities.mm_images` (PDF butuh `mm_pdf`).

**Thinking / reasoning:** Web **tidak punya** param `thinking:{type,budget_tokens}` (itu API resmi). Web memakai setting percakapan/akun **`paprika_mode`: `"extended"` | `null`** — dikirim di body completion (`body.paprika_mode`), di `create_conversation_params`, dan via `PUT …?rendering_mode=raw` `{settings:{paprika_mode}}`. Mode UI: Auto / Extended / Instant; model mendeklarasikan `paprika_modes` / `thinking_modes`; jika model baru tidak mendukung mode saat ini, ia reset ke `null`. Thinking tiba sebagai blok `type:"thinking"`: `{type:"thinking", thinking:"…", start_timestamp, stop_timestamp, cut_off:bool, summaries:[{summary}]}`. Parse `thinking_delta` / `thinking_summary_delta` / `thinking_cut_off_delta` dari stream. Gateway memunculkannya tiga cara: (a) tag `<think>…</think>` inline di konten OpenAI (yushangxiao), (b) delta thinking sebagai stream terpisah (chat-cli), (c) tidak sama sekali (aurora, cyberanrhy). Error berbeda: `thinking_messages_rate_limit_exceeded` = limit pesan thinking mingguan.

**Internet / web search:** **Tidak ada gateway yang mengekspos web search.** Mekanisme web yang mendasari adalah **setting percakapan**, bukan field body completion: `enabled_web_search: boolean` (setting sticky, bertahan lintas percakapan), plus `enabled_bananagrams` (Drive), `enabled_sourdough` (Gmail), `enabled_foccacia` (Calendar), `enabled_mcp_tools` (objek pemetaan UUID server → bool), `tool_search_mode: "auto"|"off"`. Di-set saat pembuatan (di `create_conversation_params` / settings) atau via `PUT` settings. Entri tool bawaan: `{type:"artifacts_v0",name:"artifacts"}`, `{type:"repl_v0",name:"repl"}`, `{type:"project_knowledge_search",…}`, `{type:"widget",…}`. Di stream, web search muncul sebagai blok `tool_use` (nama `web_search`) + `tool_result` dengan kutipan; konten pesan juga membawa chip kutipan. Mode deep-research terpisah: `compass_mode:"advanced"` (konstan `Tre`); menyalakannya auto-mengaktifkan `enabled_web_search`; jika semua tool search dinonaktifkan, `compass_mode` auto-clear ke `null`. Tugas riset mem-poll `…/task/{id}/status` (status: `starting|planning|initiating_agents|searching|creating_artifact|completed|cancelled|timed_out|failed`, interval ~30 dtk) dan bisa dihentikan via `…/task/{id}/stop`. Model harus mendeklarasikan `capabilities.web_search` / `compass`.

**Trik, pitfalls, limitasi penting (lintas repo):** **TLS fingerprinting adalah blocker #1:** `requests`/`httpx` polos → 403 dari Cloudflare. Pendekatan yang jalan: `curl_cffi` impersonate `chrome110` (Python), `bogdanfinn/tls-client` profil Chrome (Go/aurora), `rquest` (Rust, per chat-cli), atau `urllib` (claudexit mengklaim lolos). Di Rust, rencanakan `rquest` sejak awal. **Auth lebih dari `sessionKey`:** satu referensi menyatakan `sessionKey` saja memberi 403 — semua cookie claude.ai + `User-Agent`, `Referer`, `Origin` diperlukan. Mode full-cookie adalah jalur robust; Bearer-only adalah fallback terdegradasi. `sessionKey` adalah HttpOnly — salin dari DevTools → Application → Cookies, bukan `document.cookie`. **Expiry sesi:** 401 → salin ulang cookie; `lastActiveOrg` bisa hilang → `GET /api/organizations`. Tidak ada refresh background di tool-tool ini; panggilan berikutnya gagal dan user paste ulang. **Rate limit:** 429 = jendela kuota (free tier ~20 msg/hari per satu repo; reset harian ~09:00 lokal per repo lain — perlakukan keduanya sebagai tergantung akun, bukan kanonis); kode retryable `429/529/500/502/503` dengan backoff eksponensial (2/4/8/16/32 dtk, ≤5 retry, hormati `Retry-After`); thinking punya limit mingguan sendiri; tambah delay antar-op (1–3 dtk) untuk pekerjaan bulk. **Switching org:** UUID org per-akun; pool multi-akun harus menjaga cache org + cookie per akun, jangan pernah berbagi. **Kebersihan percakapan:** create-per-request + hapus setelah pakai (kalau tidak sidebar penuh / history bocor); penghapusan sendiri butuh retry. Persistensi `conversation_id` harus per-akun dan diserialisasi per percakapan. **Gating model:** ketersediaan model free vs Pro; model terdaftar ≠ model bisa dipakai; switch model bisa diam-diam meng-clear `paprika_mode`/`compass_mode`. **Angka usage palsu** di aurora (berbasis panjang); tidak satu pun proxy ini mengembalikan token count asli. **Drift frontend:** `anthropic-client-sha`, nama tool ter-obfuscasi, payload `tools`, param query bootstrap, dan flag pembuatan inline semuanya berubah seiring rilis web — capture trace HAR/DevTools segar saat sesuatu rusak, dan munculkan kode error upstream mentah. **Risiko ToS (semua repo):** proxy-proxy ini memakai sesi web di luar pemakaian yang dimaksudkan; akun bisa di-flag / sesi diinvalidasi. Jaga pacing request mirip manusia (cf. lantai 1,5 dtk cyberanrhy).

**Referensi pendukung (bukan gateway, tapi dokumen protokol terbaik):** [iweisc/claude-interceptor — lifecycle percakapan](https://github.com/iweisc/claude-interceptor/blob/HEAD/docs/extraction/claude-conversation-lifecycle.md) dan [research/thinking](https://github.com/iweisc/claude-interceptor/blob/HEAD/docs/extraction/claude-research-thinking.md) — diekstrak dari bundle frontend claude.ai. Pakai sebagai ground truth untuk payload completion, settings, dan bentuk SSE.

(3) Payload `tools` yang dikirim aurora (reverse-engineered dari request browser asli) — tidak dipublikasikan di docs-nya; capture dari sesi live. (5) Apakah `provider-claude` chat-cli melakukan upload file asli atau hanya fence `<<<FILE:…>>>`.

Imagine **edit** adalah alur terkini paling terdokumentasi — lihat [PR #940](https://github.com/chenyme/grok2api/pull/940): `modelName: imagine-image-edit`, `mediaGenInput.imageToImage: {prompt, inputAssets: [<fileMetadataId dari upload-file-v2/direct>]}`, `kind: CONVERSATION_KIND_IMAGINE`, plus `enableImageStreaming / enableSideBySide / sendFinalMetadata` dan `responseMetadata.modelConfigOverride.modelMap.imageEditModel: imagine`. - Thinking: Reasoning sisi model; Build mengekspos `grok-4.6` dengan reasoning effort `xhigh`. Console `grok-4.20-0309-reasoning` melakukan reasoning tapi **menolak `reasoningEffort` yang bisa dikonfigurasi**. Gateway memunculkan reasoning di Responses/Messages dan bisa me-replay-nya.

Preflight `/rest/media/post/create` legacy, `parentPostId`, `videoGenModelConfig`, `temporary: true` dihapus karena bentuk basi diam-diam mengembalikan video demo yang tidak terkait sambil menghabiskan kuota. Video Web: 720p di Basic, 480p di Super (per README). `size` gambar adalah alias aspect-ratio; `resolution`/`quality` diabaikan di Web (nama model memilih produk). - Trik/pitfalls: Egress di-scope per provider; clearance FlareSolverr terkelola (proaktif / on-demand / manual); retry egress hanya gagal koneksi pre-submission — tidak pernah me-replay generasi yang sudah disubmit, gagal auth, kuota habis, atau rate limit. Sync model dibuat async untuk menghindari timeout 100 dtk Cloudflare. Perbaikan anti-bot di [PR #567](https://github.com/chenyme/grok2api/pull/567): format fallback `x-statsig-id` harus `x1:<error>`, bukan `e:<error>` (lihat §4e).

### 4e. Detail Grok lintas-potong untuk reimplementasi Rust
**Auth & anti-bot (bagian sulit):** Set cookie (grok.com): `sso` (primer), `sso-rw`, varian `ssoBasic` + client lama juga mengirim `x-anonuserid`, `x-challenge`, `x-signature`; plus `grok_device_id`, `__cf_bm`, `cf_clearance` dari pemanasan `GET grok.com/`. Header `x-statsig-id` wajib di panggilan REST. Tiga generasi workaround teramati: (a) **trik fallback** — `btoa("x1:" + <string error JS>)`, yaitu base64 dari `x1:` + nama variabel error acak; server memvalidasi prefix `x1:` (prefix `e:` lama → 403). (b) **Derivasi penuh** — nilai meta publik 48-byte `grok-site-verification` + kunci animasi spesifik deployment + counter detik-sejak-2023-05-01 + SHA-256 + byte salt acak + XOR + base64 tanpa padding; inputnya adalah (metode HTTP, path relatif origin), **bukan** body; TTL token ≈ 20–45 dtk, mint segar per request. (c) **Oracle browser** — tab Playwright di grok.com memanen token live (fork mengirim sidecar `statsig-signer`: `POST /sign {method, path, environment.metaContent} → {x-statsig-id}`). Lane WebSocket tambahan butuh token request Castle (`castle.io`) ~14 KB — alasan lain untuk tetap di lane REST. **TLS fingerprinting penting:** impersonasi `curl_cffi` Chrome (mis. `chrome131`) dipakai sebagai bypass Cloudflare; TLS default `reqwest`/polos bisa kena 403. Di Rust, rencanakan HTTP client yang mampu impersonasi TLS (atau route lewat layer fingerprinting), plus akuisisi clearance gaya FlareSolverr sebagai fallback. Catatan sandbox: egress proxy MITM kena 403 oleh Grok — validasi live butuh jaringan non-sandbox. Material Statsig **spesifik deployment dan berotasi per page load**; jangan pernah hard-code nilai hasil capture.

**Checklist bentuk request (grok.com `conversations/new`)** — field yang terlihat lintas sumber: `temporary`, `modelName`, `message`, `fileAttachments[]`, `imageAttachments[]` (lama) / `fileAttachments` tergabung (saat ini), `customInstructions`, `deepsearch preset` (spasi literal) / `deepsearchPreset`, `disableSearch`, `disableTextFollowUps`, `enableImageGeneration`, `enableImageStreaming`, `enableSideBySide`, `imageGenerationCount`, `isPreset`, `isReasoning`, `returnImageBytes`, `returnRawGrokInXaiRequest`, `sendFinalMetadata`, `toolOverrides{}`, `forceConcise`, `webpageUrls[]`. Multi-turn: entah replay history (stateless) atau `POST conversations/{id}/responses` + `parentResponseId`. `temporary: true` = tanpa history (default di client minimal; `false` di client lama).

**Parser streaming (grok.com):** Baris NDJSON; frame pertama bisa membawa `result.conversation {conversationId, title, …}`; token teks di `result.response.token` dengan `isThinking` (→ `reasoning_content`) dan `messageTag: final`; berakhir di `isFinished: true`; teks final penuh di `result.response.modelResponse.message` (dengan `responseId`, `parentResponseId`). Normalisasi ke event internal: text / thinking / image / image_progress / annotation (kutipan, sumber search) / soft_stop / skip. Imagine: frame gambar / frame video streaming (`result.response.streamingVideoGenerationResponse.videoUrl` di `progress: 100`, prefix `https://assets.grok.com/`); media final di bawah `assets.grok.com/users/<uid>/generated/…`.

**Vision:** Terima URL atau URI `data:`; unduh/decode → `POST upload-file-v2/direct` → `fileMetadataId` → referensi di `fileAttachments`; untuk edit Imagine, oper id sebagai `mediaGenInput.imageToImage.inputAssets`. Jangan kirim base64 mentah tanpa wrapper Data-URI.

**Thinking:** `isReasoning: true` dan/atau varian model `-thinking` dan/atau `reasoning_effort` (none/minimal/low/medium/high/xhigh); `none` menonaktifkan thinking. Reasoning yang di-stream = token dengan `isThinking`. Waspadai stream terdegradasi "missing-thinking" (jawaban terlihat, tanpa reasoning) — chenyme memperlakukannya sebagai kegagalan kualitas dan me-retry akun lain.

**Search:** `disableSearch: false` untuk mengizinkan search; `toolOverrides` search web/X per §4c (verifikasi live — bukti konflik); DeepSearch via key preset; kutipan tiba sebagai anotasi stream — kumpulkan, jangan andalkan mereka inline di teks. Lane Console juga meneruskan rentang waktu X-search.

**Kuota / limit / penanganan kegagalan:** Kuota chat (README Python): Basic 80 req / 20 jam; Super 140 req / 2 jam. Video 720p ≈ 8 per jendela 18 jam (`POST /rest/media/imagine/quota_info`). Sync kuota setelah generate (`/rest/rate-limits`). Petakan status upstream: `429` → cooldown + coba akun lain; `401` → akun unauthorized; `403` → reset sesi transport / refresh clearance; `5xx`/transport → retry terbatas. Jangan pernah me-replay generasi yang sudah disubmit saat retry. **Drift protokol adalah norma:** chenyme menghapus (bukan mendepresiasi) jalur Imagine basi karena diam-diam mengembalikan output salah sambil menghabiskan kuota. Pin dan verifikasi ulang payload terhadap capture browser live; perlakukan capture cache yang lebih tua dari beberapa minggu sebagai mencurigakan. **Konflik gating tier yang perlu verifikasi live:** README chenyme mencantumkan model gambar Imagine sebagai tier Basic; catatan sebelumnya bilang Grok Imagine butuh langganan berbayar. Jangan hard-code keduanya — probe dengan akun aktual. Catatan privasi: percakapan Grok bersama secara historis pernah terindeks mesin pencari; utamakan `temporary: true` kecuali user mau history.

**Sumber pendukung (Grok):** [mem0ai/grok3-api](https://github.com/mem0ai/grok3-api) (541 bintang, diarsipkan, client minimal paling awal), [lowkruc/web2api](https://github.com/lowkruc/web2api) + [dok provider Grok](https://github.com/lowkruc/web2api/blob/master/docs/providers/grok.md)-nya (lineage Python yang sama, dokumen arsitektur terbaik), [CNFlyCat/GrokProxy](https://github.com/cnflycat/grokproxy/blob/HEAD/README.md) (proxy `sso`-cookie sederhana). ## Catatan lintas-provider untuk build Rust modular (satu file per provider)

1. **Auth adalah cookie di mana-mana, bukan API key.** Gemini: `__Secure-1PSID` + `__Secure-1PSIDTS` + `SAPISID` (+ scrape XSRF `SNlM0e`). ChatGPT: JWT `access_token` (diterbitkan via `/api/auth/session` dari `__Secure-next-auth.session-token` atau refresh token OAuth) + `_puid` + `ChatGPT-Account-ID`. Claude: `sessionKey` (`sk-ant-…`) — mode full-cookie adalah jalur robust, Bearer-only terdegradasi. Grok: cookie `sso` (+ `grok_device_id`, `__cf_bm`, `cf_clearance`, header `x-statsig-id`). Keempatnya: utamakan cookie hasil export Firefox di mana rotasi terlibat (DBSC Chrome merusak rotasi Gemini); persist token yang terotasi ke disk; ada jebakan degradasi diam-diam (Gemini → anonim, Claude → 403).
2. **TLS fingerprinting adalah masalah sulit yang universal.** Tiap pintu depan web provider di-gate Cloudflare. Pendekatan yang jalan di lapangan: impersonasi `curl_cffi` Chrome (Python), `bogdanfinn/tls-client` (Go), `rquest` (Rust), relay browser Playwright/CDP sebagai fallback. Di Rust, evaluasi `reqwest-impersonate` (impersonasi Chrome berbasis BoringSSL) atau `rquest` sejak awal; rencanakan fallback browser-relay (octo-lex ChatGPT membuktikan POST direct bisa 403 bahkan dengan sentinel benar + TLS impersonasi).
3. **Format streaming berbeda per provider — normalisasi sejak awal.** Gemini: frame `wrb.fr` length-prefixed → inner JSON, teks kandidat di `inner[4]`; thought tiba sebelum teks body. ChatGPT: SSE JSON-patch v1 (add/replace/append/remove/bulk-patch) + replay segmen → butuh ledger emisi per-turn + deteksi replay untuk delivery tepat-sekali. Claude: dua bentuk SSE (legacy `type: completion` + event content-block gaya Anthropic modern); parse `thinking_delta` / `thinking_summary_delta` / `thinking_cut_off_delta`. Grok: NDJSON; teks di `result.response.token`, flag `isThinking`, berakhir di `isFinished: true`. Bentuk target: event internal (text / thinking / image / image_progress / annotation / tool) → SSE OpenAI.
4. **Vision = upload-lalu-referensi di mana-mana.** Gemini: upload resumable ke `content-push.googleapis.com` → referensi WIZ blob; butuh cookie; re-upload per request. ChatGPT: layanan file 3 langkah (`POST /backend-api/files` → `PUT upload_url` → `POST …/uploaded`) → `image_asset_pointer: file-service://<file_id>` di bagian `multimodal_text`. Claude: wiggle upload (`/conversations/{id}/wiggle/upload-file`) → (dokumen saja) `convert_document` → `attachments` (inline) atau `files` (ref `file_uuid`); gambar lewati convert. Grok: `upload-file-v2/direct` → `fileMetadataId` → `fileAttachments`; edit Imagine via `mediaGenInput.imageToImage.inputAssets`. Jangan pernah kirim base64 mentah tanpa wrapper Data-URI (Grok secara eksplisit gagal).
5. **Thinking/reasoning adalah mekanisme per-provider, bukan flag generik.** Gemini: toggle UI `-thinking` yang ortogonal terhadap model dasar; thought di-stream sebagai `reasoning_content` sebelum teks body; `@think=N` terbukti salah (index turn). ChatGPT: slug model (varian `-thinking`) dan/atau `thinking_effort` (`none/minimal/low/medium/high/xhigh/max`); stream tipe konten `thoughts` / `reasoning_recap`; echo `thinking_effort` adalah cermin request, bukan bukti — validasi terhadap katalog per-model. Claude: setting akun/percakapan `paprika_mode: "extended" | null` (tanpa param `thinking:{budget}` di web); blok thinking via event `thinking_delta`; dimunculkan sebagai tag `<think>`, stream terpisah, atau tidak sama sekali tergantung gateway. Grok: `isReasoning: true` dan/atau varian model `-thinking` dan/atau `reasoning_effort`; reasoning yang di-stream = token dengan `isThinking`; `none` menonaktifkan thinking.
6. **Web search TIDAK punya flag per-request eksplisit di protokol yang didokumentasikan repo mana pun.** Gemini: search native warisan, tidak ada flag didokumentasikan (satu commit fork menyebut penambahan grounding ke payload generate — belum terverifikasi). ChatGPT: model auto-putuskan via tool `search`-nya; protokol teks `<tool_call>` emulasi membiarkan tool search sisi-client jalan, tapi server tidak pernah mengeksekusi tool. Claude: setting percakapan `enabled_web_search` (sticky, bertahan) + array `tools` dengan entri web-search ter-obfuscasi; `compass_mode: "advanced"` untuk Deep Research auto-mengaktifkannya; tidak ada gateway yang mendemonstrasikannya end-to-end. Grok: `disableSearch: false` + `toolOverrides` search web/X + key preset DeepSearch — bukti konflik (capture 2026-08 tidak menemukan toggle di lane WebSocket). **Untuk keempatnya, toggle search yang deterministik harus diverifikasi dengan menangkap request live dengan toggle search UI web menyala dan membedakan body.**
7. **Hitungan usage/token palsu atau estimasi di mana-mana.** Gemini: backend tidak mengembalikan count asli (estimasi `chars/4` atau tiktoken). ChatGPT: Aurora mensimulasikan token cache; tidak ada endpoint kuota standalone. Claude: usage aurora berbasis panjang. Grok: kuota via `/rest/rate-limits` / `quota_info`. Desain gateway Rust untuk melaporkan usage estimasi dan melabelinya demikian.
8. **Postur anti-abuse (bersama):** Limit per-egress-IP (Gemini terukur: 80–180 req sebelum halaman sorry 302, pemulihan ~120 menit; pace lembut 10 req/menit jalan 800 tanpa blok), rate limit per-akun + cooldown, pool akun dengan health scoring + failover pre-first-byte, pairing sticky akun↔egress, reuse koneksi, pacing mirip manusia (Claude: lantai 1,5 dtk). Jangan pernah me-replay generasi yang sudah disubmit saat retry (Grok). Param sampling (`temperature`, `top_p`, `max_tokens`) diterima-dan-diabaikan di web Gemini; gptweb2api secara eksplisit me-400-kan mereka sebagai `unsupported_parameter` daripada diam-diam mengabaikan — utamakan perilaku penolakan eksplisit.
